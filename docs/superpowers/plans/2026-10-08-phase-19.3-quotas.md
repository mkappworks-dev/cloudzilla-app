# Repository Count and Storage Quotas Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** An owner can be capped at a number of live repositories and a number of bytes on disk, with both limits off by default.

**Architecture:** A `QuotaService` checks the count before every `claimRepo`, tracks `repositories.size_bytes` with a coalescing background measurer, and caps each push at the space left by lowering the push's `LimitedReadCloser` once the ref commands are read. Web commits and wiki edits check the storage quota in the handler. A nil `*QuotaService` allows everything, so tests that don't use quotas leave it unset.

**Tech Stack:** Go, chi, viper, Templ.

## Global Constraints

- Every quota at `0` changes nothing, and costs no query.
- A superadmin's personal account is exempt; orgs never are.
- A push that only deletes refs is never capped.
- Comments state only a *why*, in one line by default.
- Stage files by explicit path. Never stage `.claude/`.
