Install Cloudzilla

Cloudzilla is a self-hosted Git platform written in Go. This guide walks through getting a working instance running locally in under five minutes.

Quickstart

The fastest path is the official Docker image. It bundles the server, SSH transport, embedded migrations, and a PostgreSQL-ready binary.

docker run -d \
  -p 8080:8080 -p 2222:2222 \
  -e CZ_DATABASE_DSN="postgres://..." \
  -e CZ_AUTH_JWT_SECRET="$(openssl rand -hex 32)" \
  -v $PWD/repos:/var/repos \
  ghcr.io/cloudzilla/cloudzilla:latest

Open http://localhost:8080 and you'll land on the setup wizard. The first user to complete setup becomes the instance superadmin.

Create your first repo

From the dashboard, click New repository in the header. Pick an owner, a name, and a visibility — and you're done. Cloudzilla creates a bare repo on disk and gives you both an HTTPS and an SSH clone URL.

Set up SSH

Add your public key under Account settings → SSH keys. Cloudzilla speaks the smart-HTTP protocol on port 8080 and a pure-Go SSH server on port 2222 — no git binary required on the server.

# clone over SSH
git clone ssh://git@your-host:2222/mkappworks/cloudzilla.git

Architecture at a glance

  • Backend: Go 1.23+, chi router, sqlx, go-git, cobra CLI
  • Frontend: Templ (type-safe Go HTML), HTMX for partial updates, Tailwind CSS
  • Database: PostgreSQL
  • Layering: stores → services → handlers, strict separation

The CLI ships as cloudzilla-cli alongside the server binary. Use it for migrations, admin user management, and one-off scripts.

REST API

Most product surfaces have a REST equivalent. Endpoints are documented under /api/v1/* with standard JSON responses. Authentication is via either the cz_token cookie (browser) or Authorization: Bearer header (API clients).

Webhooks

Webhooks fire on push, issues, and pull_request events. Set the optional secret to sign payloads with HMAC-SHA256. See Repository settings → Webhooks.
