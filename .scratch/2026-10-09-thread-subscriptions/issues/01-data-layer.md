## What

Migration 113 creates `thread_subscriptions` as in the spec, with a CHECK on `kind`, `state` and `reason`. Add `model.ThreadSubscription`, `store.ThreadSubscriptionStore` (wired into `Stores`) and `service.ThreadSubscriptionService` (wired into `Services`).

Store methods: `Upsert` (sets state and reason), `InsertIfAbsent`, `Get`, `ListByThread(state)`. Service methods: `Status(ctx, userID, repo, kind, number)` returning state and reason with the repo-watch fallback, `Set`, `AutoSubscribe` (insert-if-absent), `SubscribeOnMention` (upsert), `SubscribedUsers`, `MutedUsers`.

## Agent Brief

**Category:** enhancement
**Summary:** Persist a per-user, per-thread subscription state for issues, pull requests and discussions, with a service other features call.

**Current behavior:**
Only repo-level watches exist (`watches`, levels `watching`/`releases_only`/`ignoring`). Nothing records interest in, or a mute of, a single thread.

**Desired behavior:**
A `thread_subscriptions` table holds one row per `(user, repo, kind, number)` with `state` (`subscribed|muted`) and `reason` (`author|comment|review|mention|assign|manual`); `kind` is `issue|pull|discussion`. Rows cascade when the user or repo is deleted. A service answers the viewer's effective state: the row if present, else "subscribed (watching)" for a `watching` repo watch, else not subscribed; a `muted` row beats a repo watch. Writes come in two flavours: insert-if-absent (auto-subscribe, never changes an existing row) and upsert (manual choice, mention).

**Key interfaces:**
- Model, store and service for thread subscriptions, wired into the `Stores` and `Services` aggregates.
- Service operations: status for one user and thread, set state, auto-subscribe, subscribe-on-mention, list subscribed users of a thread, list muted users of a thread.

**Acceptance criteria:**
- [ ] The migration applies cleanly and enforces the allowed `kind`, `state` and `reason` values.
- [ ] Deleting a user or repo removes their rows.
- [ ] Auto-subscribe leaves an existing row unchanged; set and subscribe-on-mention overwrite it.
- [ ] Effective-state rules above hold, including muted over a repo watch.
- [ ] Store integration tests and service tests cover every operation.

**Out of scope:**
- Notification fan-out, UI and API routes (later tickets).
- Org-level or user-level watching.
