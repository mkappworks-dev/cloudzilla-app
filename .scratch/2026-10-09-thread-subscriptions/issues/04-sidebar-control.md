## What

Per `mock.html` tab 1: a Notifications section with a Subscribe/Unsubscribe button, a "Muted" pill and a reason line, on `issue_detail.templ`, `pull_detail.templ` (replacing the repo-watch button at ~294-322) and `discussion_detail.templ`. One fragment under `internal/view/fragments/`, one view-model in `internal/view/viewmodels_*.go`, one handler pair for `PUT /api/repos/{owner}/{repo}/{issues|pulls|discussions}/{number}/subscription`, route in `internal/router/router.go`. The PUT re-renders the section via HTMX; no page reload or session-storage toast.

Hidden for anonymous viewers. The reason line texts are the ones in the mock; muted shows "You won't be notified unless someone @-mentions you."

- [ ] The control never changes the repo watch.
- [ ] 401 for anonymous, 404 for a repo the caller can't read, 422 for a bad `state`.
- [ ] Render tests per page; `docs/api-reference.md` documents the endpoint.

## Agent Brief

**Category:** enhancement
**Summary:** Add a Subscribe/Unsubscribe control to the issue, PR and discussion sidebars, backed by the thread subscription.

**Current behavior:**
The PR sidebar's "Subscribe" button is really a repo watch and reloads the page. Issue and discussion pages have no control.

**Desired behavior:**
Each of the three pages shows a Notifications section (logged-in viewers only) with a Subscribe or Unsubscribe button, a "Muted" pill when muted, and a one-line reason (e.g. "You commented.", "You're watching this repository.", "You muted this thread. You won't be notified unless someone @-mentions you."), as in the approved `mock.html`. Clicking toggles via a `PUT` to a per-thread subscription endpoint (`state` of `subscribed` or `muted`) and swaps the section in place via HTMX. Subscribe writes `subscribed/manual`; Unsubscribe writes `muted`, even if the user only watches the repo. The control never changes the repo watch. The PR page's repo-watch Subscribe button is removed.

**Key interfaces:**
- `PUT /api/repos/{owner}/{repo}/{issues|pulls|discussions}/{number}/subscription` with `{"state": ...}`; 401 anonymous, 404 unreadable repo or missing thread, 422 invalid state.
- One shared fragment and view-model used by all three pages.

**Acceptance criteria:**
- [ ] All three pages render every state in the mock and toggle without a reload.
- [ ] Subscribe and Unsubscribe write the states above; the repo watch is untouched.
- [ ] Error statuses as listed.
- [ ] Render tests per page and handler tests.
- [ ] `docs/api-reference.md` documents the endpoint.

**Out of scope:**
- Rewording or changing the repo Watch control.
- A settings page listing subscriptions.
