SSH host key rotation breaks existing client fingerprints #214

open Locked

yumi opened this issue May 12, 2026 · 2 comments

Y yumi opened May 12, 2026

I rotated the host key on our staging Cloudzilla node yesterday. Now every existing SSH client is throwing REMOTE HOST IDENTIFICATION HAS CHANGED warnings — which is technically correct, but breaks unattended deploy jobs that can't accept the new key interactively.

Two things would help:

  • Document the rotation procedure (include the ~/.ssh/known_hosts remediation step).
  • Optionally support publishing the new fingerprint via an HTTPS endpoint so CI can auto-update.
